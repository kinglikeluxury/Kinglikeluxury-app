Admin-Only WhatsApp API Chat History

Goal:
Create a new admin-only section in the admin menu named:

WhatsApp API Chat History

This section must be visible ONLY to the main admin.
It must NOT be visible to:

- regular users
- employees
- sub-agents
- non-admin roles

Purpose:
Allow the admin to view all WhatsApp Cloud API conversations in one place, similar to WhatsApp Web.

Required features:

1. Admin Menu
   Add menu item:

WhatsApp API Chat History

Route:
/admin/whatsapp-api-chat-history

Admin-only access.

2. Conversation List

Show all WhatsApp API conversations grouped by customer phone number.

Each row should show:

- customer phone number
- customer name if linked to CRM lead
- last message preview
- last message time
- unread count if available
- source:
  Meta Lead / CRM / Manual / AI / Unknown
- assigned agent if linked to CRM

3. Conversation Detail

When admin opens a number:

Show full message history like WhatsApp:

- incoming messages from customer
- outgoing messages from API / AI
- timestamps
- delivery status if available:
  sent
  delivered
  read
  failed
- message type:
  text
  button reply
  list reply
  template
  media if available later

4. Store Messages

If current system does not already store WhatsApp API messages, create additive tables only.

Suggested tables:

- whatsapp_api_conversations
- whatsapp_api_messages

Do not delete or modify existing tables.

5. Data Sources

Include messages from:

- Meta WhatsApp Cloud API outbound sends
- AI WhatsApp messages
- future inbound webhook messages

If inbound webhook is not yet implemented, design the table and UI so incoming messages can be added later.

6. Privacy / Permissions

This page is admin-only.

Employees and sub-agents must not access it.

Server-side permission check required.
Frontend-only hiding is not enough.

7. Search and Filters

Add:

- search by phone number
- search by customer name
- filter by unread
- filter by assigned agent
- filter by date range

8. Safety

Do NOT modify:

- Meta Leads sync
- Silk registration
- Developer Registration Center
- Email nurturing
- WhatsApp sending logic unless only adding logging/storage of sent messages
- CRM lead creation
- payments
- authentication logic except route protection
- public website

9. Important

This task should not send any WhatsApp messages.

It is only for:

- storing
- displaying
- auditing
- reviewing chat history

10. Validation

After implementation:

- Admin can open /admin/whatsapp-api-chat-history
- Non-admin receives 403
- Menu item visible only to admin
- Existing WhatsApp API sent messages appear if available
- New outgoing WhatsApp API message is stored in history
- Conversation detail opens correctly

Return:

- files changed
- routes added
- database tables added
- permission checks
- screenshots or verification
- confirmation no unrelated systems were changed
